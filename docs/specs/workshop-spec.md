# Workshop: Kip and Truck in one place (draft 1, 2026-11-02)

One standalone page, `/kip/Workshop.html`, with a tab per bench. It exists so the Kip configurator and the mechanical truck can be tested together, and so their shared pieces (rig, menu, print view) can be unified step by step, before any of it moves into the game.

## Name

**Workshop.** "Factory" is already the game's stage (`?tab=factory` in `src/App.tsx`, `ToyCustomizer` "World Factory", the Factory missions), and this is meant to land there, so a second Factory would make "merge Factory into Factory" ambiguous. The only other "workshop" is the old worktree/branch `worktree-workshop` (the Describe tab), which is finished and on disk.

Stage 1 deliberately embedded whole pages (replaced in 4b, see the 4b record; this paragraph is why it started that way). What it bought: one place to open both, a tested tab and URL contract, no edits to files other sessions own, a hidden bench is unloaded (its WebGL context is freed), and the host boundary the game needs (`mountWorkshop(el, { urlSync: false })`, no globals, does not touch the host's URL or title). What it did not buy, and 4b does: one WebGL context, a bench that keeps its state while you look at the other, and no frame boundary. Still open: the two benches have their own menus and print views, and the shell cannot yet carry wardrobe/print state from one bench to the other except the shared Kip driver (4c).

## Contract the shell keeps (tested in `tests/workshop.test.ts` and `scripts/e2e-workshop.mjs`; module host since 4b)

- `?bench=<id>` picks the bench; every other query param is forwarded to it when it is mounted (`?bench=kip&vehicle=truck`, `?bench=truck&driver=snap&head=fox`). A bench is mounted the first time it is shown and then stays mounted: a plain tab pick shows it as it is (state, camera and all), and only an address whose forwarded params differ from what is mounted (a deep link, or Back to one) reopens it as the link says. A deep link to the Truck never loads the Kip module.
- A tab pick pushes history; Back and Forward step between shell states.
- A bench's own link to another bench's page (the Truck's "Kip Viewer") switches the tab: it is recognised by file name, the default navigation is cancelled, and tab, title and address bar change with nothing reloading.
- The shell knows no bench internals (no `kipMenu`, `__KIP_READY__`; a test greps for it). It reaches a bench through the mount function named in `DEFAULT_BENCHES` (`{ id, label, src, module, mount, note }`), the shared services it hands over (`env.stage`, `env.sharedKip`, and since 4c `env.sharedMenu` and `env.sharedPrint`: one menu panel and one print view, each optional for a bench), and the handle that function returns (`{ root, ready, dispose, frame, setActive }`). A new bench is one entry plus a module that exports its mount function.
- No iframe (a test checks `workshop.js` and `Workshop.html`). The page itself needs camera permission for the selfie; there is no frame permission list to maintain.
- `mountWorkshop(el, { urlSync: false })` leaves the host's URL and title alone and needs no globals; each bench publishes its `window.kip*` style handles on its own object, which the shell returns from `handles(id)`.

## Print view for the Truck (stage 3), from reading the code

Checked:
- `resolveSceneBom(state, opts)` in `kip-print-bom.js` takes Kip's scene state (edition, vehicle, head, prop, colours). Its part-to-STL tables are hard-coded and name the `veh_*` cover, chassis and wheel parts. It names none of the Truck's ids (`kit_*`, `pro_*`, `mom_*`, `mech_*`: 0 hits).
- All 42 part ids the Truck loads have entries in `public/kip/partspec-validation.json`: 33 pass, 9 pass with warnings (kit_keel_base, both steer knuckles, mom_bellows_base, mech_drive_tray, mech_brain_tray, mech_servo_mount, pro_pilot_pin, mech_sill_duct), 0 pass with settings. The plate tiers therefore have data to work from.
- The Truck draws assembly-pose copies (`public/kip/partspec/mockup/`, regenerated by `sync_truck_kip.py`); the print view needs the print-frame STLs (`_S` / `_P`) the validation index names. A part can print rotated relative to its assembly pose (`print.rotation_deg` in the manifest); 9 Truck parts do: kit_barbell_shaft, kit_yoke_hbar, pro_tie_rod_link, pro_captive_pin_28, pro_steer_column, shaft_tu03, mom_wind_key, pro_pilot_pin, char_faceplate — axles, pins and shafts lying flat with axis horizontal ([90,0,0], tie rod flipped [180,0,0]).

So the extension is a provider interface, `getParts() -> [{ id, colour, count }]` plus how to find each part's print STL, that Kip's resolver implements today and the Truck implements next; colour and plate planning stay as they are.

Pre-work checks (2026-11-02, from the validation details, the PartSpec manifest and the print planner):

- **Warning parts on the Ender-3 Pro profile: no different setting needed.** All 9 warnings are the single check `V8_wall_thickness` (regions under 0.8 mm; worst points 0.03–0.76 mm — slivers, not structural walls), all need brim 0, and all 42 parts are `supports: false`. That is 0.4 mm-nozzle geometry, identical on the print view's `standard_220` profile as under the `fdm_pla_0.4` validator; the planner derives its support tiers from its own V4/V5 report anyway. At most, note "detect thin walls" in slicer guidance.
- **Moving-assembly layout: seat native, default Standard fit.** Connector fit classes across the 42 parts are PIN 38, FRICTION 26, PIN_DRIVE 9, PIN_FREE 3 — the mechanism mixes structural friction joints with free/drive pins, so the provider must not flatten fits; the profile's `FIT_OPTIONS` compensation (snug 0 / standard 0.10 / easy 0.26 mm, calibration-kit ladder) stays global, with Standard as the Truck default and Easy as the documented escape for a stiff steer/rack stage. The 9 rotated parts must be seated in their manifest print pose (axles and pins lying flat, layer lines along the axis, never re-seated upright — the provider marks them print-posed, as Kip's PartSpec entries already are).
- **Sprue/kit-card: loose plates by default, sprue opt-in for static shells only.** Everything fits the 170 mm sprue bound (largest part kit_keel_base at 124.8 mm) and nothing needs supports, so sprue layout is geometrically possible; but sprue nubs on rack/gear teeth, knuckle pivots and shaft flats would foul the mechanism, and small pins (pro_pilot_pin: 48 mm² bed contact) adhere better loose. The Truck provider therefore plans loose plates and only offers sprue cards for static shell parts (keel, trays, tub, windscreen).

## Stage 4 scope (2026-11-02, from reading both pages at 693da4a)

**What each bench is today.** One inline `<script type="module">` per page (`Kip-Demo.html` 3166 lines, `Truck-Mockup.html` 2089). Each creates its own renderer, scene, camera, `OrbitControls`, one `requestAnimationFrame` loop, one `keydown` and one `resize` handler on `window`. Both already import the same `vendor/three-kip.js`, `kip-rig.js`, `kip-vehicles-wardrobe.js`, `kip-faceplate-shape.js`, `kip-forge-sdk.js` and `mountPrintView`, so the shared layer exists; what is not shared is the scene and the Kip instance. Each page builds its own Kip with `createKipRig` (the Truck passes `KIP_BUILD_VERSION: 'truck-1'`); the "one Kip" work in bdde691 unified the hair and hat slots, not the instance.

**What would clash in one document.**
- DOM ids: only `viewport` and `status-text` are shared by both pages (38 and 43 ids in all), so namespacing is small.
- `window` handles: Kip sets 7 (`__KIP_READY__`, `kipMenu`, `kipPrint`, `kipRig`, `kipClips`, `kipDescribe`, `kipSelfie`), Truck sets 4 (`__TRUCK_READY__`, `__truckProbe`, `__truckProbeSweep`, `truckPrint`). Eight scripts and tests read them (`e2e-kip-menu`, `e2e-kip-print`, `e2e-kip-selfie`, `e2e-workshop`, `kip-plate-check`, `kip-menu.test`, `workshop.test`, `stl-hero-rig.test`, plus the describe host), so the standalone pages must keep publishing them.
- Look: tone-mapping exposure 0.92 (Kip) vs 1.04 (Truck); fog on Kip only; environment intensity 0.55 on Truck only; camera fov 34 / 36, near 5 / 1, far 4000 / 2000; the Kip renderer is `alpha` with `preserveDrawingBuffer` (screenshots, selfie), the Truck's is not. A shared scene needs a per-bench look preset, not one global setting.
- Listeners and GPU objects: nothing disposes today (the page is the lifetime). A bench module needs `dispose()` that removes its `window` listeners, stops its loop and frees geometries, materials and textures.

**Sub-stages.** Each one ships on its own and is checked by `npm run e2e:workshop` plus the two bench suites.

### 4b-3 shared-Kip record (2026-11-03)

Built as designed below: a stage-owned session, not either bench reaching into the other's module scope. - Add `kip-session.js` with `createKipSession({ THREE, STLLoader, mergeVertices, toCreasedNormals })`. - A session is reference-counted and leased to at most one bench at a time. The stage already calls the previous bench's `setActive(false)` before the next bench's `setActive(true)`, which is the handover point: stand-down snapshots and detaches `rig.mover`; activation borrows it and adds it to that bench's scene. A bench mounted while the other bench owns the rig must finish loading without stealing `rig.mover`.

Kip adopting a session already used by Truck initializes its corresponding `loco` fields from the session rather than resetting the driver.
- Bench teardown detaches the mover before `disposeThreeScene`, then releases one session reference. Only the last release disposes session geometries and materials; disposing either bench while the other remains mounted must leave the surviving bench renderable.

### 4c record (2026-11-03): one menu, one print view

**What it is now.** In the Workshop there is ONE menu panel and ONE print view. A bench no longer draws its own controls or its own plate view; it *declares* them, and the shell's single instances show the declaration of whichever bench is active.

- **The menu** (`kip-menu.js`). `mountKipMenu(ctx)` draws `ctx.groups()` (a bench's own sections) or, without it, the Kip's `buildMenu(ctx)`. One panel can be pointed at another bench: `rebind(ctx, { root })` / `park()`. `createMenuHost()` is what a bench talks to: `show(id, ctx, { root })` when it becomes active, `hide(id)` when it stands down. The shell makes one (`env.sharedMenu`); a bench mounted on its own makes a private one and shows it at once, exactly as before. Folded groups and the collapsed rail are remembered across a switch (by group id), and so is "Leo Explorer, edited" (the preset tracking now lives on each bench's ctx). The panel moves into the active bench's root, so `H` / `?ui=0` (`.clean-ui`) still hide it. Why one instance and not one per bench: two panels in one document repeat every `km-*` id, so a `<label for>` can point into the wrong one; the e2e checks that no menu id is repeated.
- **The Print group** is `buildPrintGroup(pr)`, extracted from `buildMenu` and exported. The Kip's menu and the Truck's declaration both use it, so the same controls, ids and words appear on both tabs. Stickers and 3D stencils are hidden when the source has no artwork (`summary.art === false`).
- **The Truck's sections** are `truck-menu.js` (pure, no browser globals, unit-tested): Stage (the ladder as one select + Action demo), Motion (dump tip, steer lock, explode), Options (giant tyres, bulldog nose, plow, the three jet selects while in 2b, X-ray, auto steer, drive), Driver (Kip driver on/off, rig, head, hair, hat), Camera (four presets), then Print. `TRUCK_STAGES` and `TRUCK_CAMERAS` are plain data. **The Truck's own dock, phone drawer and print panel are gone, standalone too** (no second UI to keep in step): the bench is about 280 lines shorter (2,352 to 2,073): markup, CSS and click handlers became `setStage`, `setGiantWheels`, `setDumpTip`, ... and a `truckMenuApi` of `{ get, set }` pairs at the end of the mount. Range controls take a function for `min`/`max` (the dump tip's minimum depends on the stage). A clicked switch drops its focus (selects already did), or the Truck's drive keys and Space would be swallowed by the panel after one mouse click on "Drive".
- **The print view** (`kip-print-view.js`). It asks for a *source* each time it needs one: `ctx.source()` for a host, or `ctx` itself for a standalone bench (so every old call keeps working). A source is `{ id, scene, getState, setCharacterVisible, renderStickerSources? }`, plus `getParts()` and `getKipState()` for a mechanism bench. The view keeps the source it opened with until it exits, and abandons an `enter()` whose bench was switched away during planning. `bench-print.js` `createPrintHost` shares one view between benches (`register(id, source)`, `release(id)`; `mountPrintView` is injected so it loads in Node). When a bench stands down it releases first, so plates open on its parts close before it saves its camera.
- **The merged BOM** (`kip-print-bom.js`): `mergeBoms([...], { stickers })` and `resolvePrintBom(source, ...)`. A mechanism bench prints its parts and, when "Kip driver" is on, the Kip driver with them, made by `resolveSceneBom` from `truckDriverPrintState` (`truck-print-parts.js`). The driver is printed *as the Kip bench has it dressed* when that bench is mounted (`kipSession.registerPrintState` / `printState()`: the session holds only a function, like `registerSync`), else in the wardrobe defaults; the Truck's own head/hair/hat/rig win over the Kip's copies of those four. The Kip's own vehicle, prop, back and tail are hidden while it sits in the cab, so they are not in the BOM; its custom head and crown STLs are kept.

**Decisions made while building (tell me if any is wrong).**
1. **The driver prints on the Truck tab with the truck, and "Kip driver" off leaves it out.** Pro stage: 55 parts on 2 plates together (24 truck and 31 driver; the truck alone was 24 parts on 2 plates); the Truck still defaults to "All together", the Kip to "Split by colour", remembered per source (the choice used to be per bench; it is now per *source* in one view).
2. **No stickers or stencils on the Truck tab.** A mechanism bench has no artwork renderer, so the Kip's face sticker would export an empty sheet; the BOM drops the decals and the Print group hides the two toggles. They print from the Kip tab. Not built: the driver's face art from the Truck tab.
3. **The truck is not a "vehicle" to the planner** (`group: 'truck'`, planned with the character group). The profile's "Include vehicle" switch is shared by both benches; if the truck were a vehicle, turning it off on the Kip tab would silently drop the whole truck from the Truck's plates.
4. **The printer profile is now one object in memory.** Before, each bench's view read it from storage once at mount, so a fit or printer chosen on the Kip tab did not reach the Truck's view until a reload (the e2e checks this).
5. **The watcher sees what is built, not just three fields.** The Truck's watched state includes a signature of its part list, so changing wheels, nose or plow while the plates are open now repacks them (before, only stage, driver and head did).
6. **`kipMenu.ctx` stays the bench's own.** Each bench publishes the shared panel's handle with `.ctx` fixed to its own (`Object.create(handle, { ctx })`), so the many scripts that read `window.kipMenu.ctx.loco` keep working, hosted or not. `controls` / `fields` are the panel's, i.e. whichever bench holds it.

**What the mount has to do (the steps, in order).**
1. **Prove the entry import (spike, half a day).** `public/` files cannot be imported by literal path from `src/` in Vite (dev: "Cannot import non-asset file ... inside /public"), and a variable path is rewritten to `/kip/workshop.js?import`, which the dev server answered with a 500 (checked on a running dev server by the research). Everything below the entry loads natively and is unaffected.
2. **A host component** (`WorkshopHost.tsx`) that calls `mountWorkshop(el, { urlSync: false })` and `destroy()` on unmount; the shell already needs no globals and leaves the URL and title alone.
3. **The grown-up print gate: a blocker, not a polish item.** The viewer's gate only engages when the page is *framed* (`isEmbeddedFrame(window)`), and the answer is read from `window.parent`. A module mounted in the game's top window therefore downloads print packs **with no grown-up check at all**. The seam exists (`ctx.printGate` in `mountPrintView`, and `createPrintHost({ printGate })`) but no bench or shell forwards one. Build a callback-style gate (`request(kind)` opens the game's Grown-Ups step, the answer calls back into the view) from the game's primitives (`requestGateChallenge` / `verifyGateAnswer` in `parentTime.ts`, the `GrownUpsSheet` hold, math and PIN steps, the server's `x-parent-proof`); do not rely on `postMessage`, because at top level a self-posted message would pass the `source === window.parent` check. Do not ship the mount without it.
4. **CSS isolation.** No Tailwind, but the game has global rules that reach the benches: `[hidden] { display: none !important }`, `button, input, select { font: inherit }`, the 3 px `:focus-visible` outline, h1 to h3 and `p` margins, the 15 px body type, `color-scheme: dark`. The benches' reset is `:where(...)` (specificity 0) so the game wins ties; the modals' `h2` and `p.modal-sub` would take the game's margins. Expect a visual pass. The menu's `.km*` / `#kip-menu` / `#km-style` are document-global, which is safe now that there is exactly one panel.
5. **Paths that resolve against the page, not the module** (fine at `/kip/Workshop.html`, broken at `/`): `./partspec/mockup/*.stl` and `./partspec/mockup/kip_stack.json` in `truck-bench.js`, one in `yard-bench.js`, `./selfie-faces/` in `kip-selfie.js`. 6. **Serving and caching.** Prod has `not_found_handling: single-page-application`, so a missing `/kip/*.js` answers 200 with HTML (a MIME error, and a missing STL parses HTML): the host must catch a failed mount and offer a retry. `public/sw.js` serves `/kip/` cache-first by URL, and several imports carry no `?v=` (`truck-bench.js`, `bench-stage.js`, `truck-print-parts.js`, and now `truck-menu.js`, `bench-print.js`): bump `CACHE` with every deploy that changes a viewer module, or add the version query.

Camera: the selfie's `getUserMedia` has a seam (`ctx.getUserMedia`), `kip-bench.js` calls it directly; the game has none and no permissions policy blocks a top-level mount. Storage the benches write: `kipMenu.collapsed`, `toyforge.printerProfile.v1`, `toyforge:prop-lang:v1` (shared with the game); read: `toyforge:progression:v1`, `toyforge:device:v1`.
