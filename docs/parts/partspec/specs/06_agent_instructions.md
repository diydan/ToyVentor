# ToyVentor: agent instructions

> Generated by `make_agents.py` from `interfaces.json` v0.4.0-draft and `toyventor_parts.json`. Do not edit by hand: change the source, then regenerate.

## What this is

ToyVentor parts (Snap for kids, Pro for makers) are generated by code, described by a manifest with typed connectors, and assembled into designs. This file tells you how to change the model and how to build designs from it without breaking compatibility.

Status: TARGETS ONLY - nothing has been printed yet. Values lock after the calibration piece has been through fit loops on a real printer. Verified so far only for brick, plate and Forge Mount geometry; add-ons and capsules still need re-proportioning to the TU lattice.

## Rules

1. `interfaces.json` is the single source of truth for numbers, limits, check severities, safety constants and print-page warnings. Never hard-code a value that exists there.
2. Change the source first (`interfaces.json` or the part code), then regenerate. Generated files are never the source: the STLs, `toyventor_parts.json`, `toyventor_index.json`, `INTERFACE_STANDARD.md` and this file.
3. Never invent connector kinds, interface ids, check ids or part ids. The schema and the catalog below define what exists. If something you need is missing, report the gap instead of working around it.
4. Prefer existing parts to new ones, and keep each change small.
5. Before changing an interface number, run the impact query and recheck every part it lists.
6. Never report a physical check (`F1_printed_fit`, `F2_breakage`) as passed. They stay pending until a real print.
7. Use only parts whose `design_status` is `verified` in designs, unless the user says otherwise. The generator computes `design_status` from the checks; never set it by hand.
8. Do not name third-party construction systems or their trademarks in part names, specs, UI text or comments.
9. Do not describe any part as safe for children under 3. That needs a lab test and is outside what this model can show.

## Workflow

```text
task -> impact query (index) -> smallest edit to interfaces.json or part code -> generate -> read failing checks
     -> build_check (assembly demos) -> regenerate standard + agents -> selftest
```

Leave the model valid: `generate` must report no blocking failures and `selftest` must pass before you finish.

Before a new or changed part ships, run `python3 preprint_check.py --catalog --part <id>` (see `PREPRINT_VALIDATION.md`). Its report must not be `fail`, and any `print_settings` it gives (a brim) travel with the file.

## Creating or changing a part

A part conforms when its status is `verified`. No blocking check fails, the small-parts screen is not marginal, and a Large part clears the small-parts cylinder. Pending physical checks do not count against it. Otherwise it is `needs_reproportion`. design_status is computed by the generator from the check results. It is never set by hand.

1. Pick the line, the size class and the interface the part exposes (an entry in `interfaces`).
2. Add a catalog row (`catalog.json`) with `family`, `size`, `build`, `type`, `behavior` and `tags`. A row in a family (block, tile, slope, dome) needs no code. A bespoke part (add-on, capsule, Pro part) names one function that returns (manifold, connectors, extras), built with `block()`, `stud_conn()`, `socket_conn()` or the Pro primitives so geometry and metadata cannot drift. Take every number from `interfaces.json`.
3. Run `generate`. Read every failing check, fix the geometry or the row's parameters, and run again until no `block` check fails and the small-parts result is not `marginal`.
4. Run `build_check`, regenerate the standard, agent and catalog files, then run `selftest`. All must pass before the part is used.

Rules every part follows:

- Never type a footprint. The foot comes from the interface, so it is on the lattice by construction.
- Body dimensions drawn at the old 8 mm scale are multiplied by `limits.addon_body_scale`. Walls, clearances, fillets and embed depths are print-limited constants and are not scaled.
- Nothing tilted or curved above the foot may leave an underside steeper than `limits.max_overhang_deg`. Bury roots in the foot and let `keep_above()` trim them flush.
- If the small-parts result is `marginal`, resize the part until it is clearly inside or clearly outside the cylinder. A Small part may be `small_part` (ages 3 and up, carries the warning). A Large part must be `above_cylinder`.
- A part has exactly the connectors it physically has. Never claim a mate the validator does not enforce.
- Fit-critical cylinders (studs, tubes, bores) use `limits.fit_segments` polygons. A coarser cylinder shrinks the printed gap by more than the design gap.
- Every mating feature is fit-measured. If a part adds a new kind of mating feature, extend `seat_pair()` so `fit_report()` measures it; a connection the fit check cannot see is not verified.
- When a family parameter puts a part in the marginal small-parts band, change the parameter in the catalog row (a Small slope uses 30 degrees, not 45), not the family code.
- A round outline cannot carry studs on the lattice: the cavity must reach the corner studs, which needs a 28.4 mm outline against a 24.8 mm footprint at Small. Use a dome or other female-only shape on the standard foot.
- A part may print in a different orientation than it assembles (pins and shafts lie on a flat for strength along the axis). The part returns `print_rotation_deg`; printability checks (bed, overhang, bridge, small parts) run on the printed mesh, connector checks run in the assembly frame, and the STL is exported as printed.
- On a square Small 2x2 foot, keep the part under about 25 mm tall or over 57 mm: the foot is 33.8 mm across its rounded diagonal, so anything in between measures marginal in the small-parts screen however it is shaped. Use a larger foot (Small 4x4 or Large 2x2) for a tall Small-line part.
- Add-ons and capsules use an integrated base (`base: integrated`): no plate around the part, stud holes in its own underside. A shape too thin for a hole gets a small pad on two lattice points (`pad`), and a part whose direction matters (`lock`) needs two holes, or one hole plus a relief that keys it against a neighbouring stud; the generator refuses it otherwise. Every integrated part is checked sitting on a full plate, so no stud can hit it where it has no hole.

## Lattice and interfaces

One base unit: 1 TU = 12.5 mm. Every interface pitch is an integer multiple of the TU, so all product lines share one lattice. Snap Small = 1 TU, Snap Large = 2 TU, Pro holes = 1 TU (halving to 1/8 TU). Snap Large studs land on every other Pro bore position; Snap Small studs land on every Pro bore position.

| Interface | Kind | Size class | Pitch (mm) | Fit class | Clearance (mm) |
| --- | --- | --- | --- | --- | --- |
| `stud_small` | stud_grid | small | 12.5 | FRICTION | 0.1 |
| `stud_large` | stud_grid | large | 25.0 | FRICTION | 0.1 |
| `bore_grid` | bore_grid | pro | 12.5 | PIN | n/a |
| `pin_friction` | pin | pro | 12.5 | PIN | n/a |
| `pin_free` | pin | pro | 12.5 | PIN_FREE | n/a |
| `shaft_drive` | pin | pro | 12.5 | PIN_DRIVE | n/a |
| `c_jaw_tu01` | c_jaw | pro | 12.5 | SNAP_JAW | n/a |
| `flank_rail_tu02` | mortise | small | 12.5 | FRICTION | n/a |

Each size has its own clearance value (stud_small.fit, stud_large.fit). Both start at 0.10 mm as placeholders. Print clearance does not scale linearly with part size, so Large is expected to need more; the calibration piece sets both.

## Building a design

Never write coordinates. Pick parts and connectors; the library computes the pose so alignment is correct by construction.

```python
from toyventor_assembly import Library, place, attach, validate
lib = Library('out/toyventor_parts.json')
ring  = place('forge_mount_ring', pid='ring')
brick = attach(lib, ring, 'top_studs', 'big_blue_brick', 'under_sockets', parent_cell=(0, 0), child_cell=(0, 0), pid='brick')
result = validate(lib, [ring, brick])   # {'ok', 'errors', 'warnings', 'edges'}
```

The validator enforces: stud_grid with socket_grid, pin with bore_grid. Pin-and-bore pairs must be listed in `pin_bore.rules`. Pose is limited to turns about z, so pins run along z; perpendicular pins (cross holes) arrive with the T beam in W4.

When `validate` rejects a build, read the code and fix it:

| Code | What to do |
| --- | --- |
| `unknown_part` | The part id is not in the catalog. Pick an id from the catalog table. |
| `duplicate_id` | Every placement needs a unique id. |
| `size_mismatch` | The two connectors have different size classes. Choose a child part whose connector has the same size class as the parent's. |
| `misaligned` | The parts touch on the same plane but no studs line up. Use attach() with explicit parent and child cells instead of raw coordinates. |
| `floating` | A part is not connected to the first placement. Attach it to something with attach(). |
| `profile_mismatch` | A pin and a bore that `pin_bore.rules` does not allow together (a round pin in a fixed bore, for example). Use a pin profile the bore class accepts, or a different bore. |
| `gear_mesh_distance` | Two gears (or a gear and a rack or ring) reach each other but are not at their meshing distance: m (z1 + z2) / 2, m (z_ring - z) / 2, or the pitch radius from a rack. Move one by a bore or pick a tooth count that fits. |
| `unsupported_pose` | A stud or socket part was tipped over. Stud parts stay upright; only Pro parts tip. |
| `collision` | Two parts occupy the same space. Move one to a different parent cell, rotate it, or choose a smaller part. |

Warning `unverified_part` means a part is not re-proportioned to the current lattice. Treat that design's geometry results as unreliable.

## Fit and tolerance

After each part is built, the generator seats it on its matching reference part, slices both at mid-stud height and measures the radial gap of every engaged stud. `T1_fit_as_designed` (block) requires the measured gap to equal the design gap and to sit inside the limits (max play 0.2 mm, max interference 0.1 mm). `T2_fit_tolerance_window` (warn) requires it to stay inside those limits when printers are calibrated to +/-0.05 mm per surface. `build_check` also fit-measures every mating pair in the catalog (`fit_matrix.json`) and every connection in a build.

**Calibration target:** every part fits when the printer's surface offset is inside -0.071 to +0.075 mm (the intersection of all part windows). An uncalibrated printer (+/-0.1 mm) is outside that window, so calibration is required.

## Safety

Every part is screened against the small-parts cylinder (31.75 mm across, 25.4 to 57.1 mm deep). The screen is conservative and is not a lab test. The print page shows the general notice plus the text for the part's status:

- **always:** Printed at home or by a print service. Not tested to toy-safety standards. Adult supervision required. Check for cracks, sharp edges and loose pieces before each use, and stop using anything that has broken.
- **small_part:** CHOKING HAZARD - Small parts. Not for children under 3 years.
- **marginal:** This part is close to the small-parts size limit. Treat it as not suitable for children under 3 years.
- **above_cylinder:** Larger than the small-parts test size in our size check. This is not a safety certification, and it is not rated for children under 3 years.

Small parts are for ages 3 and up. A warning label is enough only for parts sold to ages 3 and up.
