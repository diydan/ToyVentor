1 · Training: did it learn, and did it memorise?

How to read it. The typical AI training chart plots loss (how wrong the model's answers are on example answers, lower is better) against steps (small updates). The faint orange line is the loss on each batch of training examples, the bold orange line its running average. The blue dots are the evaluation loss, measured every 50 steps on examples the model never trained on. Both falling and then flattening together means it learned the pattern; evaluation loss climbing while training loss keeps falling would mean it was memorising. Same axes on every panel (log scale).

What it says here. Final evaluation loss is between 0.116 and 0.128 for every pilot on file, and no pilot's evaluation loss ends more than 0.01 above its own best: no sign of memorising. The short-prompt pilots 1 and 2 start much higher (about 1.0 against about 0.2); the two prompt styles are different tasks for the model, so absolute loss values are not comparable between the two groups. In our case an "example" is a child's wish with our own base model's printable answer for it; low loss means the tuned model writes answers like those. It says nothing about whether the part prints, is fast or is safe: that is what the pass-line charts below measure.

2 · The two dials behind the curve

How to read it. The learning rate is how big a step each update takes: training starts with a very short warm-up, then the step size shrinks steadily so the model settles instead of bouncing. The gradient norm is how hard the examples are pushing on the model at each step; a healthy run is steady, a sudden climb means the training is going unstable.

What it says here. Pilot 5: the learning rate reaches its peak of 2.0e-4 after 6 steps and then falls in a straight line to about zero by step 508; the gradient norm sits mostly between 0.2 and 1 with its median at 0.3. Nothing here suggests a blow-up. One thing worth knowing: pilot 8's very first step had a gradient norm of 9.3 against a median of 0.6 for the rest of that run; it came straight back down.

3 · Score against the pass line

How to read it. A trained model is judged on a set of test examples it did not train on, against the model you already have (the base). Here there are five measures from the decision rule we fixed before any run. Each chart is one measure: the square is the base, each dot a tuned run, the green zone is the side that passes, the dashed line is the pass line (worked out from that group's own base). A dot's colour is backed by the words "pass" / "fail". The two groups are separate on purpose: after the first results we found the name filter wrongly blanked all seven names for harmless short wishes such as "ninja hat" (in every model, the base too). We fixed it with Dan's approval, so older runs (v1) and newer runs (v2) were measured with different rulers and are each judged against their own base.

What it says here. Pilot 8 (p8) under the fixed name rule: passes every check. Its filter count is 6 against a line of 6: exactly on the line, so one wish either way flips the result. Pilot 8's dots sit close to their pass lines on several charts, so a small change in one run could flip a result; that is why charts 5 and 6 look at spread and repeated runs.

5 · How long does a child wait?

How to read it. One dot per wish, placed by how many seconds it took end to end (wishes that should make a part, same set for every row). The solid line is the median (half the wishes were faster), the grey line the p90 (nine in ten were faster). Dots are spread up and down only so they do not hide each other. Runs shown are the fixed-rule (v2) ones.

What it says here. Median 28.4 s for the base against 13.2 s for p6, 13.1 s for p8, 13.4 s for p8 again; the slowest tenth (p90) is 51.7 s for the base against 24.9 s, 22.6 s, 23.8 s. The tuned dots are packed to the left and the long tail is shorter, so a child waits about half as long, also in the bad cases. Times include the real pipeline (model, optimizer, gates) and two wishes sharing the laptop.

6 · Is one run enough? Run-to-run noise

How to read it. Each row is one model (or the base); each mark is one full run of the same 243 wishes. Circles are runs measured with the old name rule, diamonds with the fixed one (so a gap between a circle and a diamond is partly the ruler, not the model). The bar spans the lowest to the highest run and the numbers at the right give that range. If the bar is as long as the margin a pass or fail was decided by, one run cannot decide.

What it says here. The spread between runs of the same model is as big as the margins we are judging by: filter-fix counts differ by base 0, pilot 5 4, pilot 6 5, pilot 8 2, printable share by base 0, pilot 5 0.6, pilot 6 0.7, pilot 8 1.3 points, median seconds by base 4, pilot 5 4.8, pilot 6 0.8, pilot 8 1.7 s (rows with one run omitted). The base itself moves too: its filter count was 12 and 12, but the two sets of wishes that fired differ in 10 places, which matters because the safety line is "half the base's count". That is why a pass in one run is called a qualified result, not a proven one, and why repeats come first in the plan.

7 · New brands the model never saw (blind set, dev half)

How to read it. A model can look good on the examples it was built around and fail on new ones. The blind set holds 404 wishes written separately from the training wishes; only its dev half (204) is used here, and its test half is kept sealed for one final look per candidate. The brand wishes ask for 12 characters and brands that are on neither our training list nor the production filter ("a Cocomelon hat"). A tuned model passes one when its own name and text for the part carry no brand name.

What it says here. On brands that were in no list, the base run is not finished; pilot 8 76.2%. Dev half, one run each, brands never seen in training: a pointer, not a result. Wishes and translations are unreviewed by a native speaker.

9 · What a real, full-size version of this would add (not done)

  • A bigger, blind test set. Several hundred wishes, read by native speakers, kept out of every design decision. Ours has 404 items, unreviewed, and only its dev half has been used. not done
  • Repeats with confidence intervals. Each wish asked three times or more, results given as a range, so a pass is not decided by one wish. We have two or three full runs for a few models. not done
  • A "does it match the wish?" score. Printable only means it passes the gates. A person or a judge model would rate whether the part looks like what was asked. Unmeasured. not done
  • A native-speaker read. Of the word lists, the test wishes and the seven languages of names. None has happened. not done
